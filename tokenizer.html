Tokenizer & Fertility

Why an India-first model needs its own tokenizer: an English-centric one charges Indic scripts 2–4× more tokens for the same text — wasting training and inference budget on Hindi.

How to read this page

A tokenizer chops text into tokens; the model pays per token. Fertility = tokens per word — lower is cheaper. The root cause of the Indic tax is physical: an ASCII letter is 1 UTF-8 byte, but a Devanagari or Tamil letter is 3 bytes. A byte tokenizer that learned English merges but no Indic merges falls back to raw bytes for Indic, so one Hindi letter becomes ~3 tokens.

Switch the tokenizer profile below and watch the token boxes: character (1 per letter), English byte-BPE (Indic letters explode into their raw bytes), and Indic-aware (1 per grapheme cluster — the fix). Every count here is exact (UTF-8 bytes, code points, Unicode grapheme clusters). A real learned tokenizer (tiktoken / SentencePiece) is a documented offline tier. Note: real English tokenizers do merge English into words — the point is Indic gets no such benefit.
